# 平台账号与 DeepSeek Harness 共享凭据

状态为待评审。2026-11-17 已确认平台管理员可以查看和管理所有项目，创建者保留项目所有者权限。

## 本期范围

关闭本地账号自助注册，规范 `admin` 和新建本地账号的初始密码，验收平台管理员对所有项目的管理权限，并为 DeepSeek Harness（DSH）工作台对话和平台托管 SOP 提供共享凭据。CodeBuddy 的凭据行为、第三方登录原有接入策略和普通用户既有的项目可见性沿用现行规则。远程独立 Runner、Bot、报告和助手定时任务沿用各自的凭据规则。WorkBuddy 单列为后续可行性验证。

## 账号和首次登录

| 场景 | 目标行为 |
| --- | --- |
| 访客打开登录页 | 页面提供登录和联系管理员的提示。空库与已有账号的实例均关闭注册和首次建号入口，旧注册链接只能进入登录页。直接访问旧注册接口和首次设置接口返回 `404`。部署配置不能重新开启自助注册。 |
| 新部署 | 运维显式初始化本地账号 `admin` 并授予平台管理员角色，再导入预置体验项目，使 `admin` 成为该项目 Owner。初始化密码由部署侧提供。已有的本地平台管理员 `admin` 可直接用于初始化，保留其密码和角色。若该名称被其他身份或非管理员占用，由运维显式处理冲突。重复执行不覆盖现有项目归属。 |
| 管理员创建本地账号 | 在平台管理的「成员账号」录入登录名，服务端使用部署指定的统一临时密码。未配置初始密码时，创建失败并提示管理员检查部署配置。API 和页面响应只显示账号创建结果，初始密码由管理员另行告知。 |
| 初始密码登录 | 校验初始密码成功后只允许进入改密流程。新密码不能等于旧密码。改密成功后签发普通会话，初始密码和待改密凭据失效。待改密凭据不得用于签发平台 API Token 或调用业务接口。 |
| 升级与账号恢复 | 已有账号密码、第三方身份与项目数据保留。「成员账号」的密码重置仍由管理员授权，重置后的密码走首次改密流程。旧会话和已签发的平台 Token 不得用于绕过被重置账号的待改密限制。 |

本地密码使用现有 bcrypt 存储。临时密码通过部署侧保密输入，代码、SQL、文档和构建产物只记录配置方式。账号初始化为运维显式操作，历史数据调整通过 `migrations/` 的手动 SQL 执行。

## 项目权限

| 用户 | 行为 |
| --- | --- |
| 平台管理员 | 查看所有用户的项目，包括新建项目。可以打开项目详情、修改设置、管理成员和项目仓库，以及按既有业务规则归档或恢复项目。权限由平台角色提供，新增或撤销平台角色后按当前角色判定。 |
| 项目创建者 | 新建项目后默认成为 Owner，继续拥有既有的 Owner 操作权限。页面和 API 都允许创建者管理自己的项目。 |
| 普通成员或其他用户 | 沿用既有可见性与项目内权限。普通用户不能借此编辑或归档他人的项目。 |

项目设置、仓库管理和归档接口已接受 Owner 或平台管理员，工作台也已有相同的管理入口判断。本期覆盖实际界面和 API 的权限回归，补齐发现的遗漏。平台管理员以平台角色进入项目，无需添加成员记录。普通管理操作保持原 `Owner` 和成员记录，调整归属时走现有的显式设置；项目责任人、通知接收人和凭据选用仍依照原规则。

## DeepSeek Harness 平台共享凭据

- **配置。** 「平台管理」增加 DeepSeek Harness 共享配置。只有平台管理员可以查看状态、保存和轮换 Key、配置模型白名单和停用共享。保存时要求至少一个允许模型，列表首项作为默认模型。设置接口仅返回状态和模型列表，日志只记录配置来源、操作人和结果。
- **选择凭据。** 工作台对话按对话用户判断，托管 SOP 按需求责任人判断，未指定时使用现有的项目 Owner 回退规则。有个人 Key 时使用完整的个人配置，个人 Key 无效时按原流程报错。只有没有个人 Key 的用户才走共享通道，模型目录显示共享白名单，运行时拒绝名单外模型。没有可用共享配置时提示配置个人 Key 或联系管理员。
- **使用凭据。** `UsersRepo` 负责存取共享配置，`usersHandlers` 负责管理员设置。DSH 复用现有 CLI 模型配置能力，向 LoopForge 的共享推理入口发送请求。CLI 只持有绑定 DSH 模型调用和本次执行的短期凭据。共享推理由独立 handler 负责鉴权和转发，只接受指定推理操作和白名单模型，目标为固定的 DeepSeek 官方端点，拒绝用户自定义地址和重定向。个人设置里的地址、协议以及进程环境里的配置不能改变共享请求的上游。工作台、执行日志、诊断、运行快照、CLI 配置和执行环境均不得包含上游 Key。参考 [DeepSeek Harness Provider 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.md)。
- **停用和失败。** 停用后拒绝新的共享推理请求，包括已签发短期凭据发起的后续请求。轮换后，新请求使用当前配置。已开始的流可结束。过期凭据、超出执行范围、共享关闭、名单外模型和上游错误均返回可区分的结果，响应与诊断不回显凭据。

## 验收

1. 对空库和升级库访问登录页和旧接口，确认无法公开建号。运行部署初始化后，`admin` 为平台管理员且拥有新导入的体验项目。改密并重新运行初始化，新密码和项目现有归属有效。
2. 管理员创建本地账号，两个新账号都可用部署指定的初始密码进入改密页面。验证浏览器和直接 API 调用均不能跳过改密，完成改密后可正常登录，旧密码失效。回归已有账号登录和密码重置。
3. 两个普通用户各建一个项目。两人均为自己项目的 Owner，能继续管理自己的项目。`admin` 在全量项目视图中能查看两个项目并管理设置、成员和仓库，在满足业务条件时可归档和恢复。普通用户尝试修改或归档他人的项目时被拒绝。验证管理操作前后，项目原 Owner 未变且没有为 `admin` 写入成员记录。
4. 用对话和托管 SOP 分别验证个人 Key、共享 Key、未配置、无效个人 Key、模型拒绝和停用场景。使用测试上游验证，只有转发侧持有上游 Key，恶意 `Base URL`、重定向和失效的运行凭据均无法使共享 Key 离开转发侧。补查流式输出、错误日志和诊断的脱敏，以及受支持沙箱到共享推理入口的连通性。

## WorkBuddy 后续验证

WorkBuddy 的公开接口支持用户 OAuth 授权、创建云任务和通过 ACP 接收流式回复。后续以独立适配器验证授权、发消息和接收回复。仓库工作区、人工审批和交付接入须在 WorkBuddy 云沙箱能力验证后另定规格。参考 [WorkBuddy 官方 Open API](https://open.workbuddy.cn/docs/openapi)。
